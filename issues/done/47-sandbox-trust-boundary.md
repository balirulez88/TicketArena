# 47: Sandbox trust boundary

**What to build:** a real trust boundary between the sandboxed agent and the host. The agent can no longer write the host repository, its Git metadata, the trusted orchestration scripts, host credentials or the authoritative batch and resume state. Agent-produced commits, logs and resume data cross the boundary only as data. A trusted host step validates them and accepts them before anything is merged or pushed. Resolves TD-057 in `docs/technical-debt.md` (HIGH). Until this merges, autonomous production batches are blocked. This is a harness and security change, reviewed and merged outside Ralph: a sandboxed agent must not author its own trust boundary.

**Type:** fix

**Blocked by:** None (can start immediately)

**Status:** done

**Completed:** 2026-11-04 by harness/47-sandbox-trust-boundary (reviewed and merged outside Ralph)

- [x] The container mounts no part of the host repository. Its only host mounts are a read-only input directory (a Git bundle of the base branch and parked work, plus host-held resume state) and a per-run output directory. No Docker socket, host Git metadata, GitHub credentials or batch state is reachable from inside.
- [x] Inside the container, Ralph pushes to a staging bare repository that is private to the container. At exit, that repository's branches go to the output directory as a Git bundle: data, never a remote the host pushes to or runs Git inside.
- [x] Attack path 1 (forged merge): a trusted host step (`scripts/ralph-accept.mjs`) fetches the bundle into a quarantine ref namespace with object checking, then accepts a ticket's merge only if all of these hold. The merge is exactly Ralph's shape: one squashed slice commit whose parent is the verified base, under a `Merge slice/<slug>:` commit with an identical tree. The ticket is the one that was run, was `ready-for-agent` on the base, and had all blockers `done`. The only issue-file change is that ticket's archive to `issues/done/` (`done` + `Completed`, nothing else). No protected path is touched. The full quality gate passes again on the candidate, in a fresh, agent-free sandbox. A rejected run's blocked-status commit is accepted only if it changes nothing but that ticket's status line. Anything else leaves `main` untouched and keeps the candidate for inspection only.
- [x] Attack path 2 (host-side code execution through Git): the host never runs Git inside an agent-writable repository. Fetching a bundle reads no foreign configuration or hooks. A slice that adds or changes `.gitattributes` or `.gitmodules`, or introduces a symlink or submodule, is refused, so accepting it cannot bring filters, drivers or links onto the host.
- [x] Attack path 3 (forged CI result or modified orchestration): slices may not change the harness and gate definitions: `ralph-loop.sh`, `scripts/`, `Dockerfile`, `.dockerignore`, `.github/`, `skills/`, `.claude/`, `CLAUDE.md`, `docs/workflow/`, `biome.json`, `tsconfig.base.json`, `turbo.json`, or the root `package.json` scripts. The scripts the batch runs on the host (`ralph-ci.sh`, `sandbox.sh`, ticket selection) therefore can only change through a human-reviewed commit. GitHub CI on the pushed commit remains the authority on CI.
- [x] Attack path 4 (forged checkpoints): batch state and resume state live only on the host and are never mounted writable. A pause reported by the container is accepted only after strict parsing. Its ticket and ref must match, it must sit on the verified base, `paused^` must equal `gated`, and the parked ref must be in the bundle. The host then rewrites the pause in canonical form. Anything malformed or unexpected is refused without changing host state.
- [x] Logs from the container are copied to `.ralph/logs` as plain files only (no symlinks, nothing outside the run directory) and are treated as untrusted evidence, never as decisions.
- [x] The batch (`scripts/ralph-batch.mjs`) stops finally on a refused (`untrusted`) result, rechecks a clean base checkout before every step, and keeps its limits, dependency checks, pause/resume and CI verification unchanged.
- [x] RED/GREEN/REFACTOR/DOCS, both independent reviews, the technical debt register integration and every quality gate inside the sandbox are unchanged.
- [x] Regression tests cover each attack path at the acceptance step (`scripts/ralph-accept.test.mjs`), in normal, merged, rejected, paused/resumed and interrupted runs, plus batch handling of refused results. `pnpm test:sandbox` proves the boundary through the real Docker sandbox: from inside, the host repository is unreachable and the input is read-only. A merge, a rejection, a pause and resume, and forged merges and pause state from a malicious agent all behave as specified.
- [x] `docs/workflow` and an ADR describe the trust boundary and its remaining limitations. TD-057 is `RESOLVED` with the verifying tests named in `Verification`.
