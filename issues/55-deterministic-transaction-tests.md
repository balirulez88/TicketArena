# 55: Deterministic transaction tests

**What to build:** the booking and router tests that exercise locking, saturation and rollback are deterministic: they synchronise on Postgres state instead of time, give every test its own database clients, and prove that a booking transaction which fails after its writes have begun, on a first or a retried attempt, leaves nothing behind. Spec: Holding seats; ADR 0005, ADR 0010. Split from ticket 12 (part 2 of 4, see `issues/12-lock-timeout-and-deadlock-retry.md`). Owns TD-016, TD-018 and TD-071 in `docs/technical-debt.md`.

**Reference only:** two rejected attempts of ticket 12 (branches `rejected/12-lock-timeout-and-deadlock-retry-20261106-132615` and `-20261106-165157`) may be read; their code and reviews count for nothing here. Both were rejected because a test pattern was fixed in one file and left in another: every rule below applies to every file in scope, not only to files a review names.

**Blocked by:** 54

**Status:** ready-for-agent

Scope: every test file under `packages/booking/src/` and `apps/web/src/server/` that opens a Postgres client, including the files ticket 54 added. Each criterion names its test and the sabotage that test must catch.

- [ ] Ground rules: every guarantee below is proved against the real test database (ADR 0010). No existing assertion is removed or loosened, and no test in scope is deleted, skipped or weakened to satisfy a rule here.
- [ ] One helper module: test synchronisation helpers live once, in `packages/booking/src/testing/` (files not named `*.test.ts`), exposed only through a `@ticketarena/booking/testing` subpath export and never from `packages/booking/src/index.ts`. It provides at least: a per-test client factory with disconnect, a latch, `occupy` (resolves only after the occupier's query has run inside its transaction), a session opener for blocker transactions, `waitForPg` (polls a Postgres condition), `withTrigger` (test-unique object names, removal guaranteed even when the test fails) and the shared fixtures (`NOW`, buyers, seats, recording metrics, `failureOf`). No test file in scope defines its own copy of any of them. It adds no dependency.
- [ ] Helper behaviour, tested on its own (a test file for the module): `waitForPg` fails at its deadline with a message naming what it waited for; when raced against a call that rejects first, it surfaces that rejection at once and stops polling (the test counts probe queries after the race settles: zero); a blocker session whose transaction fails while nothing awaits it reports the failure to the test instead of leaving an unhandled rejection; `withTrigger` removes its objects when the body throws. Sabotage: removing the cancellation, or the rejection handling, turns its test red.
- [ ] Client lifecycle, in every file in scope: no module-level client and no lazily created shared client (`??=`, module `let`); each test creates its own clients through the factory and disconnects them in `afterEach` or `finally`; one-time seeding creates and disconnects its client inside `beforeAll`. Check: `rg -n "\?\?=\s*createPrismaClient|^let .*(PrismaClient|Pool)" <scope>` finds nothing,.
- [ ] No fixed waits, in every file in scope: no `setTimeout`, `sleep` or `pg_sleep` used to order sessions or to hold a lock or connection; ordering comes from latches, `occupy` and `waitForPg`. The only allowed `pg_sleep` is one inside the service's own transaction that exceeds an injected timeout. Every `waitForPg` that waits for a backend to block is raced against the call under test.
- [ ] TD-071: the saturation tests in `packages/booking/src/hold-busy.test.ts` and `apps/web/src/server/routers/booking.test.ts` occupy the pool with `occupy` and await its signal instead of a fixed sleep. Sabotage: making `occupy` resolve before its query runs makes these tests fail or flake under a delayed occupier (a test injects that delay to show the signal is awaited).
- [ ] TD-016: the clock-after-lock test synchronises on Postgres (`pg_blocking_pids`) instead of sleeps. The blocker sets a flag only after `pg_blocking_pids` shows the service blocked by it, immediately before it sends `COMMIT`; every clock read the service makes after its lock-free snapshot is stamped synchronously with the flag, and the test asserts every such read carries it (not only the last). This is sound because a clock read taken before the lock happens before the service blocks, so before the flag. The TD-016 `Resolution` states this mechanism and argument. Sabotage: reading the clock before taking the seat lock turns it red.
- [ ] TD-018, first attempt: a failure after the writes have begun (the outbox insert failing, for example a duplicate envelope id from a fixed `newId`) leaves no hold, no claim and every seat `AVAILABLE` for `holdSeats`, and leaves no order, the hold `HELD` and its seats unchanged for `placeOrder`. Sabotage: writing the outbox row outside the transaction turns them red.
- [ ] TD-018, retried attempt: in `holdSeats`, a first attempt that fails retryably (a `40001` raised by a test-scoped trigger) followed by a second attempt that fails after its writes have begun leaves no hold, no claim and every seat `AVAILABLE`, and the first attempt's rows are gone too; `deadlock_retry` = 1. Sabotage: committing between attempts turns it red.
- [ ] TD-016, TD-018 and TD-071 are `RESOLVED` in `docs/technical-debt.md`, with the tests that prove them named in `Verification` (the host refuses the merge otherwise).
